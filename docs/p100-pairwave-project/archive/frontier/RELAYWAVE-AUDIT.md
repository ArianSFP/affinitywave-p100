# RelayWave audit

## Decision

The proposed RelayWave-3500 architecture is closed before implementation by
its own `<=2250 ms` replay gate. Projection-only helper execution is exact
in principle and is retained as a possible component after a mechanism
removes arithmetic work. It is not a 3,500 tok/s architecture at the
current measured rates.

Evidence is machine-readable in `relaywave-bound-v2.json`, generated by
`relaywave-bound.py`.

## Exact contract

The helper proposal avoids the numerical failure that closed cross-lane row
pooling:

- every `(layer, lane, expert, tile index, tile class)` remains intact;
- the helper executes the original gate and up tile with the original two
  FP32 accumulator rails;
- SwiGLU produces the original 512-wide F32 middle rows;
- those rows return to the canonical owner;
- the canonical owner executes the unchanged down tile and logical-owner
  reduction.

The middle return is 2,048 bytes per routed row. It does not alter the down
dot product, BF16 owner boundary, or final logical-group sum order.

## Immutable-lane SM work floor

The replay combines:

- pre and post SM work from the existing two-panel temporal trace;
- the current exact dense selector and 40 ms measured segmentation tax;
- original-lane M64/M32/M16 counts from the final pp8128 route capture;
- the retained HalfPipe M64 factor;
- measured non-Q8 service work.

| component | aggregate GPU work |
| --- | ---: |
| pre | 5,713.665 ms |
| dense segmentation tax | 40.000 ms |
| exact Q8 | 3,147.139 ms |
| service overhead | 403.460 ms |
| post | 409.094 ms |
| total | 9,713.358 ms |

Perfect distribution across four P100s is therefore 2,428.340 ms, or
3,347.14 tok/s. This is a hard work-conservation bound before middle
returns, weight prefetch, copy-engine contention, precedence bubbles,
events, or runtime overhead.

- It misses the RelayWave implementation gate by 178.340 ms.
- It misses the 3,500 tok/s wall target by 106.054 ms.
- Even deleting all 403.460 ms of service overhead would leave a
  2,327.474 ms floor, 5.189 ms slower than 3,500 tok/s.

Projection helpers redistribute work but do not remove it, so no
barrierless scheduler can cross this floor.

## Projection-helper cache sweep

Gate/up fractions were measured from the timed lane-exact trace:

- M64: 65.998%;
- M32: 63.000%;
- M16: 65.294%.

For each budget, the offline selector keeps original tiles and moves only a
whole gate/up/SwiGLU tile from the overloaded canonical owner to the tile's
lane-home helper. The helper returns real 512-wide F32 middle rows. The
reported Q8 saving is a feasible compute assignment; middle wire time is
reported separately and is not credited as free.

| helpers/GPU | Q8 critical | saving | ceiling recovered | middle bytes | ideal wire | reclaimed |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| R0 | 1,649.773 ms | 0.000 ms | 0.00% | 0 | 0.000 ms | 1.119 GiB |
| R4 | 1,576.147 ms | 73.626 ms | 96.62% | 239,642,624 | 24.705 ms | 1.102 GiB |
| R8 | 1,574.255 ms | 75.518 ms | 99.10% | 245,671,936 | 25.327 ms | 1.085 GiB |
| R16 | 1,573.886 ms | 75.887 ms | 99.58% | 246,573,056 | 25.420 ms | 1.052 GiB |
| R32 | 1,573.886 ms | 75.887 ms | 99.58% | 245,526,528 | 25.312 ms | 0.986 GiB |
| R44 | 1,573.886 ms | 75.887 ms | 99.58% | 244,746,240 | 25.232 ms | 0.936 GiB |

The absolute perfect-balance value is 1,573.569 ms, only 76.203 ms below
R0. R4 already recovers all but 2.578 ms, and R16 all but 0.317 ms.
Increasing the cache cannot create an architectural gain.

The R16 double gate/up bank is 71,303,168 bytes/GPU. With the 131,017,728
byte N512 arena, it leaves 1,129,890,816 bytes, or 1.052 GiB/GPU, reclaimed
relative to the legacy live state.

## Full-expert replication closure

The earlier exact-T64 probes already established that R4, R8, R16, and R44
weights can be prefetched inside a long HeadFold corridor with negligible
exposure. Copy feasibility is not the missing mechanism.

Full gate/up/down replication cannot improve the 76.203 ms exact-Q8
perfect-balance ceiling. Compared with the R4 projection helper it can
recover at most another 2.578 ms, while requiring one of two worse exact
protocols:

1. return 2,048-wide F32 down results, four times the helper's middle
   traffic; or
2. move complete logical token groups while preserving tile classes with
   masked duplicate tiles.

The second protocol was replayed directly. At R44, forced complete-group
relocation made 20,165 of 67,377 original tiles execute on both partners
and raised critical Q8 work from 1,649.773 to 2,176.702 ms. Only full R128
replication removes fragmentation, reaching the 1,580.061 ms lane-home
value while abandoning the memory target.

Full-expert R4-R44 replication is therefore dominated by the smaller R4
gate/up helper and is closed.

## Retained boundary

R4 projection help is a compact, exact load-balancing primitive, but its
maximum 73.626 ms Q8 credit is below the architectural threshold and its
middle-return exposure is not yet measured. Do not integrate it alone.

Reopen it only as part of a composition that first removes at least 300 ms
of measured aggregate SM work and whose updated dependency replay clears
the desired wall target with at least 72 ms of integration margin.

## Proof-of-concept estimate and pause

The existing panelized diagonal service is already asynchronous at the CUDA
event level. Its remaining scheduler defect is that all service groups are
enqueued in a fixed order on every GPU before any cell's post graph is
submitted. A valid proof must interleave per-cell post work and subsequent
service groups across a two-diagonal window; merely deleting host waits
would reproduce the current schedule.

For that exact proof path, the realistic pp8128 range is 3000-3100 tok/s,
with about 3050 tok/s as the central estimate. A clean implementation may
reach 3150-3200 tok/s, but 3500 tok/s is impossible without reducing
arithmetic work because the perfect four-GPU SM-work floor is only
3347.14 tok/s before communication and dependency costs.

A revised proof gate would be at most 2700 ms, or at least 3010 tok/s, while
remaining byte-identical and retaining the bounded-memory service. R4 is the
only justified helper cache: it recovers 96.62% of the available Q8 balance
credit with a 17,825,792-byte double bank. The no-helper scheduling proof
must pass first.

Work was paused on 2026-07-25 at the user's request before source changes or
GPU runs. The four-GPU coordination lock was free and no project GPU process
was active.
