# InterferenceWave TileFrontier offline audit

Date: 2026-07-25

This audit is CPU-only. It does not contain a measured production runtime
claim. It uses captured train and heldout pp8128 routes, current measured
CohortRail tile costs, directed 9.7 GB/s PCIe resources, exact FlashAttention
packet costs, and the existing calibrated recurrent/dense graph.

## Retained architecture

The retained candidate is the shared b128/c6 InterferenceWave order with
exact GroupComplete reduction and TileFrontier output storage.

- CohortRail P2 items are formed only from compatible natural lane pairs
  `(0,1)` or `(2,3)` for the same layer, expert, and B pointer.
- A P2 gate/up task depends on both lane inputs. Unmatched M16 tails remain
  singleton tasks.
- Every original lane tile, row order, two accumulator rails, route rank,
  and canonical logical-owner boundary remains unchanged.
- A logical M64, M32, M16, or natural-P2 tile writes to one contiguous
  size-class output slot. There is no per-row indirect down store.
- For each `(layer, home, logical group, token)`, reduction begins only
  after all supplying down bundles complete. It consumes route ranks in the
  original order and performs the existing BF16 conversion at the existing
  canonical boundary.
- A tile slot is released only after the last exact reducer consuming any
  row in that tile completes.

The underlying b128/c6 resource sequences are byte-for-byte identical on
train and heldout for all four compute, inbound, and outbound resources.
Only route-derived reducer cohort counts differ. They are generated by the
same latest-supplier publication rule. There is no capture-specific annealed
production schedule in the retained result.

## Falsification results

- A 50,000-move corrected-DAG anneal improves train by only 0.273 ms,
  2285.334 to 2285.061 ms. The shared window/c6 order is saturated.
- b80/c6 produces exactly the same wall time as b128/c6 but creates 1500
  reducer tasks instead of 1288. It saves about 5 MB of peak dynamic storage
  but has no rate advantage.
- Publishing all 67,266 immutable logical down tiles independently creates
  65,245 reducer cohorts and 138,910 resource tasks. Its zero-overhead wall
  is exactly unchanged at 2285.334369 ms. Coarse down-bundle completion is
  not hiding wall margin.
- Exact N-panel publication is small:
  - p2 zero-overhead: 2282.578647 ms.
  - p4 zero-overhead: 2281.383504 ms.
  - p8 zero-overhead: 2280.865693 ms.
  - p16 zero-overhead: 2280.627805 ms.
  - p4 with 0.25 us per additional panel action: 2281.844567 ms.
  - p4 with 0.50 us per additional panel action: 2282.305629 ms.
  - p16 with 0.25 us per additional panel action: 2282.937805 ms.

  Without InputCascade, p4 is the only rational production probe. Its
  realistic gain is about 3 ms, so it is secondary rather than part of the
  architecture gate.
- Exact InputCascade splits each remote 2032-row FP32 hidden transfer into
  four chronological 508-row panels and subdivides scheduling bundles only
  by their latest required input panel. With c16, route planning after the
  first real panel, and 2 us charged per input panel, it reaches
  2279.741 ms train and 2279.571 ms heldout, or 3553.00 tok/s robust.
  Composing zero-overhead p4 output publication reaches 2275.531 ms train
  and 2274.129 ms heldout, or 3559.56 tok/s robust. At a more realistic
  0.5 us per additional output-panel action, p4 retains only 0.904 ms over
  InputCascade. p2 at the same 0.5 us charge reaches 2277.880 ms train and
  2277.068 ms heldout, or 3555.90 tok/s robust, and is the only rational
  output-panel companion. The complete Cascade-only memory timeline peaks
  at 126,935,040 bytes, or 121.1 MiB/GPU.
  Capacity-safe 20,000-move searches improve train by only 0.841 ms and
  heldout by 1.718 ms independently. Their robust upper bound is
  2277.039 ms wave, or 3557.21 tok/s. Because route-derived task sets differ,
  this is not one shared static order; it is a ceiling for a dynamic
  critical-priority queue and confirms order saturation.
- Whole recurrent-precompute migration is closed by byte accounting.
  It moves about 16.646 MB of input plus 66.585 MB of QKV, 33.292 MB of z,
  and alpha/beta, about 117 MB total. Ideal wire time is about 12.1 ms for
  12.841 ms compute before endpoint contention. QKV-only and z-only
  migration also lose to their ideal wire times.
- Sparse whole-group ownership is closed by corrected full-DAG replay. A
  robust MILP nearly perfects static compute balance with one through four
  changed layers, but changed input/return endpoint timing dominates:

  | changed layers | robust wave | rate |
  | --- | ---: | ---: |
  | `3` | 2301.781 ms | 3519.10 tok/s |
  | `3,15` | 2325.106 ms | 3483.92 tok/s |
  | `29,32,33` | 2314.216 ms | 3500.26 tok/s |
  | `15,32,33,39` | 2335.079 ms | 3469.09 tok/s |

  Every sparse placement is slower than fixed ownership at 2285.334 ms
  wave. Static compute balance is therefore the wrong placement objective
  under the exact endpoint and dependency geometry.

## LateFold measured-tax publication

Cross-layer PanelWeave was tested after InputCascade, corrected
GroupComplete reduction, and TileFrontier storage. It never divides or
retiles an M64, M32, M16, or natural-P2 expert tile. A chronological token
may publish only after GroupComplete's exact latest original supplier has
finished; route-rank reduction order and the BF16 canonical boundary remain
unchanged.

The ideal full four-panel transform initially appeared to reach
2252.838 ms train with 0.5 us charged per additional action. That value is
not retained. Existing bitwise exact 4x508 dense probes measure real
segmentation taxes for QKV, output, middle, down, and recurrent work.
Charging those measurements while leaving the shared expert monolithic
raises the all-stage transform to 2295.137 ms, slower than its
2278.701 ms source. Full PanelWeave with separate launches is closed. A
monolithic kernel capable of publishing panel counters without losing
monolithic throughput could reopen the ideal dependency graph, but it is
not an available implementation.

All 32 measured-tax stage subsets were then replayed. The only material
survivor, named LateFold, keeps recurrent precompute, recurrence,
attention-input work, and the shared expert monolithic. It segments only
the final output work into four exact 508-token calls:

- recurrent output panels wait for the complete chronological recurrent
  core;
- attention output panels wait for their original p127 query packets;
- remote input panels and local immutable Q8 bundles wait for the latest
  output panel containing one of their original rows;
- downstream group reduction is still the corrected per-token
  latest-supplier reduction.

The fixed tax is the measured segmented-versus-monolithic output GEMM delta,
0.168208 ms per cell, plus 0.5 us per additional panel action. Unrelated
pointwise time is not multiplied by the GEMM tax. Every retained segmented
dense selector had zero bitwise mismatches in the existing probe.

| Capture | Source wave | LateFold wave | Total | Rate |
| --- | ---: | ---: | ---: | ---: |
| train | 2278.701 ms | 2262.523 ms | 2270.423 ms | 3579.950 tok/s |
| heldout | 2278.114 ms | 2261.317 ms | 2269.217 ms | 3581.852 tok/s |
| robust | - | 2262.523 ms | 2270.423 ms | 3579.950 tok/s |

A 10,000-move train-only order search improves 2262.523 to
2261.902 ms. It is a route-specific ceiling, not the robust result. The
same deterministic ready-marker construction selected recurrent-late plus
attention-late independently on both captures, and no other stage subset
was faster. Raising the middle-slot capacity from c16 to either c24 or c32
changes train from 2262.523 to 2262.505 ms, only 0.018 ms. c16 is retained;
larger queues spend memory without a measurable scheduling return.

LateFold is still a CPU dependency replay, not a production measurement. It
creates about 27,000 resource actions and therefore assumes the retained
persistent queue rather than one host launch per action. Its robust
51.863 ms margin to 3500 tok/s must pay queue integration and runtime
effects.

The transformed lifetime has now been audited against both captures. The
timeline includes every streamed remote input panel, immutable logical Q8
output tile, gate/up middle, panelized canonical BF16 partial, home receive
panel, and locally produced late activation. It does not hide the descriptor
and event cost inside lifetime reuse, instead adding a separate 16 MiB fixed
reserve:

| Capture | dynamic peak | arena with reserve | reclaimed vs legacy |
| --- | ---: | ---: | ---: |
| train | 124.432 MiB | 140.432 MiB | 0.949 GiB/GPU |
| heldout | 140.400 MiB | 156.400 MiB | 0.934 GiB/GPU |

The heldout peak is the retained bound. It is modestly above the old
121.1 MiB Cascade-only proxy because the new audit also counts a complete
16.646 MB local late activation at the peak. No allocation grows with total
context at fixed ubatch.

The train critical-path audit also confirms that LateFold is no longer the
two-GPU-pair schedule that motivated this search. Compute-resource busy time
is 2128.147, 2178.951, 2192.716, and 2175.993 ms on C0 through C3, or
94.06%, 96.31%, 96.91%, and 96.18% utilization. The aggregate is 8675.807
GPU-ms in a 2262.523 ms wave, equivalent to 3.835 active GPUs on average.
The busiest fixed assignment leaves only 69.807 ms of ordering slack; even
perfectly redistributing all compute can expose only 93.571 ms. Placement
and scheduling are therefore close to saturation, not a path from this
replay to 4000 tok/s.

## Attention output placement closures

Two exact-order attention output placements were replayed as possible
companions to LateFold.

OutputFold assigns both original p127 packets for one 508-query panel to one
GPU, executes the measured exact segmented output projection there, and
returns only the final 508x2048 FP32 panel. It does not change either packet's
attention arithmetic. A coordinate search reduced the robust simplified
graph from 2359.142 to 2316.738 ms, but the complete train graph remained
2304.014 ms. The selected placement moved 84.447 GPU-ms of output work and
reduced 640.877 MB of packet returns to 320.438 MB of final returns, yet it
was still 41.491 ms slower than LateFold. Pairing the independently balanced
p127 packets costs more than the removed traffic. OutputFold is closed.

ContinuationFold retained the independently optimized packet destinations.
It modeled the first ordered K2048 half of each output projection on the z0
packet GPU, transfer of the 508x2048 FP32 accumulator when necessary, and
continuation through the second K2048 half on the z1 packet GPU. Its timing
uses the measured exact 4x508 M2048/K2048 selector rate, but an output
accumulator continuation kernel has not been validated and no exactness
credit is claimed. Even this favorable model reaches only 2283.858 ms train,
21.335 ms slower than LateFold, while moving 470.254 MB of accumulator state
and 441.123 MB of final panels. The mechanism is closed before kernel work.

The missing middle between independent and fully paired packet placement was
also searched. A robust coordinate pass selected 39 partial co-locations and
reduced its simplified graph by 84.089 ms. In the complete graph it reduced
ContinuationFold from 2283.858 to 2280.622 ms, still 18.099 ms slower than
LateFold. It retained 87 state copies and 98 final copies. Joint packet/state
placement therefore does not reopen continuation.

## 4000 tok/s arithmetic requirement

Current total compute work is 8648.173 GPU-ms, or 2162.043 ms under perfect
four-way balance. Exact-Q8 work is 2955.393 GPU-ms:

| Tile class | Exact-Q8 GPU work |
| --- | ---: |
| M64 | 2073.953 ms |
| M32 | 442.074 ms |
| M16 including natural P2 | 439.365 ms |

The 4000 tok/s target allows 2032.0 ms total and 2024.1 ms wave before the
fixed 7.9 ms tail. Even a perfect scheduler must remove at least
551.77 GPU-ms. If exact-Q8 alone supplies it, Q8 time must fall by 18.67%,
equivalent to at least 1.2295x throughput. If the current 100-123 ms
scheduler slack remains, the required critical-path Q8 throughput gain is
closer to 1.55-1.58x. Dense/recurrent or attention arithmetic can substitute
for part of this requirement.

For the narrower LateFold composition, measured output segmentation raises
aggregate compute to 8675.807 GPU-ms. Its perfect-redistribution floor is
2168.952 ms wave, or 3733.83 tok/s after the fixed tail. Reaching the
2024.1 ms 4000-token/s wave requires removing at least 579.407 aggregate
GPU-ms, 6.68% of all work or 19.61% of exact-Q8 work if Q8 supplies the
entire saving. No additional placement policy can remove that arithmetic
floor.

## Arithmetic and scheduler composition

The exact-Q8 durations were scaled through the complete LateFold graph
without changing task count, dependencies, copy cost, or non-Q8 work. This
is a kernel requirement surface, not a claim that any current kernel reaches
the stated rate:

| exact-Q8 speed | train rate | heldout rate |
| ---: | ---: | ---: |
| 1.2x | 3765.13 tok/s | 3768.17 tok/s |
| 1.4x | 3902.21 tok/s | 3908.62 tok/s |
| 1.5x | 3954.44 tok/s | 3962.12 tok/s |
| 1.6x | 3999.68 tok/s | 4003.84 tok/s |
| 1.75x | 4057.55 tok/s | 4062.83 tok/s |
| 2.0x | 4143.34 tok/s | 4149.62 tok/s |

A 10,000-move order search at 1.6x reaches 4001.73 tok/s train and
4011.83 tok/s heldout, but the robust train result has only 0.879 ms of
integration margin. A production-oriented Q8-only gate is therefore at
least 1.75x for 28.823 ms margin, with 2.0x providing 70.297 ms.

At 1.6x Q8, average compute occupancy falls from 3.835 to 3.738 GPUs. The
critical chain shifts from 472.324 ms gate/up plus 205.261 ms down to
616.388 ms recurrent precompute and 448.980 ms final dense work. This is why
composed arithmetic is stronger than asking Q8 to carry the target alone.
For a diagnostic composition, `dense speed` scales the complete
recurrent-precompute, recurrent/attention output, and shared-expert stage
durations. It is an end-to-end stage requirement and overstates a kernel
that accelerates only the GEMM subpart:

| Q8 speed | dense-stage speed | robust rate | target margin |
| ---: | ---: | ---: | ---: |
| 1.2x | 1.15x | 4005.80 tok/s | 2.94 ms |
| 1.2x | 1.20x | 4071.44 tok/s | 35.65 ms |
| 1.4x | 1.05x | 4000.87 tok/s | 0.44 ms |
| 1.4x | 1.10x | 4088.46 tok/s | 43.97 ms |
| 1.6x | 1.05x | 4110.25 tok/s | 54.51 ms |

All 32 measured-tax PanelWeave stage subsets were rerun at 1.6x Q8.
LateFold's existing recurrent-late plus attention-late split remains best.
Even granting every dense and recurrent stage a monolithic-throughput
partial-publication interface improves 2024.262 to only 2010.734 ms, or
4026.49 tok/s. Its 13.528 ms ceiling is useful integration margin but not a
new architecture-scale contributor.

## Implementation gate

This replay justifies an isolated proof of concept, not a production rate
claim. Implement only the following first:

1. A persistent b128/c6 device queue preserving current CohortRail natural
   pair readiness.
2. Contiguous size-class middle and output slots with backpressure.
3. Exact latest-supplier group reducers with original route-rank order.
4. Existing canonical BF16 return and owner sum.

Require byte identity at all 160 service boundaries and saved-logits SHA-256
`47e84b679f12bae440e4f743d8305699a4f01cc9e22e18418824009f346020a5`.
The hard runtime-overhead budget is 29.857 ms at pp8128; 12 ms or less is
the desired queue/counter budget.
